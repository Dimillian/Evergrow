# Loot log

The Loot log button beside Auto-sort in the inventory opens a read-only history of the character's latest 100 distinct picked-up items. It also appears in the character menu drawer and Escape pause menu’s Adventure category. Opening the log pauses combat and clears held/buffered input; Close, Escape, controller B or native Back returns to the inventory when opened there, or to the previous playing/paused state when opened from a menu. Controller directions select rows and the right stick scrolls item details. Narrow screens stack the list above the details.

Each newest-first row shows the actual procedural item icon, full name, rarity, item level and time since pickup. Selecting it uses the shared item detail renderer, including weapon values, requirements, affixes, enhancement, Greater affixes and nested Unique/effect explanations. These values describe the item when picked up; there are no equip or trade actions on historical snapshots. Time labels count active character play time, excluding offline time and pauses.

The current-location label follows the live item identity through inventory/charm cells, equipment, personal storage, active or suspended ground loot and merchant sales. Sold items also show a **Sold** label directly on their history row. Sale receipts survive buyback eviction; buying back an item clears that receipt and label. Items no longer in known locations are labeled **No longer carried**, without guessing that they were sold. Dropping and collecting an item again keeps its existing entry, original stats, first pickup time/location and position in history. Matching uses the stable item ID, so identical-looking separate items remain separate. Earlier duplicate receipts collapse on save decoding without changing inventory or progress. Deduplication covers the retained 100-item history; an item whose history has already expired can be recorded again. Gold and XP retain their dedicated reward displays.

`loot-log.ts` owns detached snapshots, the 100-entry history bound, age/location projection and staged sale updates; `loot-log-validation.ts` validates saved receipts. Simulation records only after ground-to-inventory insertion succeeds, before emitting the transient loot notice. Rejected pickups and merchant purchases do not produce pickup receipts. The optional `CharacterCheckpoint.lootLog` saves atomically with inventory and ground state; sale changes join the saved commerce candidate and become live only after success. Shared decoding validates each item, location, timestamp order and the bound. Snapshots do not count as owned gear and are not rebalanced when live items are normalized.

Existing saves start with an empty log, preserving character/world progress. Earlier pickups cannot be reconstructed. No character reset, save-version bump or database migration is required. Matching client/server validation should ship together in a future requested publication; this feature is local.

The pause entry, inventory button and log header share a drawstring loot bag icon. `LootLogPanel` uses the shared Astral window, local fonts, item UI, focus trap and explanation stack. `PanelCoordinator` owns its phase. The inventory toolbar wraps on narrow screens. `notification-layout.ts` positions the passive pickup feed without blocking world input. The passive feed retains its existing bounded presentation.

Interface → Loot log opens `/notifications.html?view=loot-log`, a frozen, disposable review with generated items and all main location states. It reads no playable saves and advances no gameplay. Headless tests cover successful/failed pickups, detached snapshots, bounds, repeated pickups, validation, save round trips, character reset/isolation, locations, sale staging and pause/input ownership. Visual feel and gameplay acceptance remain for the player to test.
